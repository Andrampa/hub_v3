DIEM Hub 3.0 · continues the household data architecture

How the Hub turns ArcGIS Online into a public front door

The Hub keeps no catalogue and no database of its own. It reads ArcGIS Online live, in the visitor's browser, along four paths: the public catalogue, household surveys, protected data and temporary microdata grants.

Current implementation · As of 22 October 2026.

How to read this diagram
  1. Read the public row from the Hub content group through catalogue services to product pages and external resources.
  2. Follow survey configuration rows and homepage statistics into the survey pages; the separate monitoring app receives URL state and a short-lived token through the embed bridge.
  3. Read the protected row as an item-by-item access check using the signed-in reader’s token. Household-data membership and temporary grants are separate paths to the same microdata picker.
  4. Follow grant discovery from the reader’s groups. The browser checks pending invitations first; the server validates them only as a fallback. The expiry job removes grant copies.
  5. Finish with the foundations: OAuth PKCE, per-tab sessionStorage and ArcGIS sharing. Signing in does not grant access to every item.

One catalogue, read live

Publishers edit items, sharing and group categories in ArcGIS Online. The Hub pages through the content group 100 items at a time, groups language variants into one product, and builds country, hazard and flood pages from categories, never from titles. Item IDs are the keys; titles and counts can change.

Membership is the public boundary

An item outside the DIEM Hub content group never appears on a public page, even if it is public in ArcGIS. Editorial flags such as "Published" control display only; confidentiality is set by ArcGIS sharing.

Sign-in opens, sharing authorizes

Signing in with a Community account opens the data workspace, but every protected item is fetched again with the user's own token, and ArcGIS decides. A typed URL grants nothing. The browser checks the recipient’s invitation metadata first. Only when that cannot confirm a grant does the server function validate the invitation against the private registry; it never returns survey data.

Where it meets the monitoring system

ArcGIS Online carries the shared data; the embed bridge also passes URL state and a short-lived token. The monitoring pipeline writes the survey config view, homepage statistics, V3 services and grant copies; the Hub reads them. The monitoring app is a separate site that the Hub frames and hands a short-lived sign-in token. See hh_survey_v3/docs/diagrams/diem_data_architecture.html.
